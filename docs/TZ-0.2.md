# Klavium — ТЗ на версии 0.2–0.3 (редакция от 12.11.2026)

Документ заменяет внешнее ТЗ в части приоритетов, дефолтов и инвариантов. Структура задач частично совпадает (редизайн, память, скорость, функции), но порядок другой: сначала устойчивость, потом внешний вид.

---

## 0. Текущее состояние (факты на 12.11.2026)

- Версия **0.1.7**, ветка `main`, установка в `E:\Program Files\Klavium` (portable-каталог `data\` рядом с exe), сборка дистрибутива — `tools/build_dist.ps1` (NSIS + portable zip в `dist\`).
- Крейты: `klavium-core` (чистая логика: детекция, конвертация, словари, хоткеи, конфиг, статистика), `klavium-platform` (Win32: хук, инъекция, оверлей, окна, раскладка), `klavium-app` (движок, голос, runtime, трей), `klavium-ui` (egui 0.31.1 настройки, меню трея).
- Хук: `WH_KEYBOARD_LL` в выделенном потоке с насосом сообщений; системный лимит `LowLevelHooksTimeout` ≈ 300 мс, при превышении Windows молча снимает хук.
- Замерено 12.11: **колбэк хука иногда 173–182 мс** на пробеле (распознавание слова идёт на потоке хука). Это главный риск потери хука и главная причина жалоб «перестало исправлять / не реагирует».
- Словари: `data/english_words.txt` + `data/russian_words.txt` (6,7 МБ), `include_str!` + `Vec<&'static str>` (~532 тыс. слов, ~8,5 МБ кучи), биграммы отдельно.
- Голос: Whisper (base ~150–250 МБ, small до ~1 ГБ) грузится в `worker_loop` сразу при старте.
- Хоткеи: `HotkeysConfig { correction_apply, card_hide, voice_toggle, quit }`, строгое совпадение модификаторов, захват — окном (egui) + очередь от хука для «немых» клавиш.
- Журнал: неблокирующий `tracing` (`<data>\logs\app.log`), уровень из конфига.
- Сборка требует `LIBCLANG_PATH=%USERPROFILE%\.libclang\clang\native` (whisper-rs → bindgen).

Сделано 12.11 и в объём ниже не входит: срабатывание хоткеев по key-up для «немых» клавиш; отпускание модификаторов перед инъекцией; реальные сочетания в пилюлях карточки; сторож хука (предупреждение в журнал); нормализация раскладки в ручном вводе.

---

## 1. Цели

1. **Никогда не «отваливаться»**: приложение обязано оставаться рабочим сутками; если что-то деградировало — это видно в журнале и лечится без перезапуска (или перезапуск предлагается явно).
2. Предсказуемый ввод: исправление не портит текст ни при каких сочетаниях хоткеев и зажатых модификаторах.
3. Настройки выглядят как современная системная утилита, а не как дефолтный egui.
4. Память: не держим модель и словари «на всякий случай».
5. Скорость: длинная диктовка вставляется мгновенно, а не посимвольно.
6. Новые функции — только после того, как база стабильна.

---

## 2. Инварианты (нарушать нельзя, это правила, оплаченные кровью)

1. **Бюджет колбэка хука**: только O(1)-операции. p99 < 3 мс, максимум < 50 мс. Никаких файлов, никакой детекции слов, никаких неопределённо дорогих Win32-вызовов.
2. **Инъекция — только через `inject.rs`** с меткой `INJECT_EXTRA_INFO`. Перед любой инъекцией — `release_modifiers()` (снять физически зажатые Ctrl/Shift/Alt/Win) и короткая пауза, иначе Backspace уходит как `Ctrl+Shift+Backspace`.
3. **Собственные инъекции не должны попадать под собственное подавление**: проверка `extra_info` выполняется до логики подавления.
4. **Хоткеи**: строгое совпадение модификаторов. Дефолты не пересекаются между собой и с частыми чужими сочетаниями (см. §8). Запрещены: `Ctrl+Shift+<буква>` (браузеры), `Alt+<буква>` (меню), F-клавиши без модификаторов (Excel, The Bat!), `Ctrl+Alt+V`/`Ctrl+Alt+G` (Office/Photoshop).
5. **«Немые» клавиши** (`Pause`, `PrintScreen`, `ScrollLock`) нельзя назначить нажатием — окно их не получает, а хук не видит, когда активно наше окно. Назначение — только ручным вводом; захват через raw input — вне объёма (см. §11).
6. **Конфиг**: только `#[serde(default)]`, старые файлы читаются без ошибок, обязательных полей нет.
7. **Наблюдаемость**: каждое действие по хоткею, каждый захват клавиши, загрузка/выгрузка модели, фолбэк вставки — строка в журнале.
8. **Тесты**: вся чистая логика — юнит-тесты в `klavium-core`; интеграционные сценарии — в `klavium-app`; перед релизом — дымовой прогон (§10).

## 3. Блок P0 — Устойчивость (1–2 дня)

### P0.1. Вынести детекцию с потока хука

**Файлы**: `klavium-app/src/engine.rs`, `engine`-вызов из `main.rs`, `runtime.rs`.

Сейчас `process_key` целиком выполняется в колбэке: `resolve_char`, буфер слова, `smart_correction` по словарям, `pending_errors_count()` под мьютексом. На пробеле это 170–180 мс.

Требуется:

1. В колбэке оставить: `resolve_char` (по скан-коду), накопление слова, отправку события в канал воркера, проверку хоткеев и `suppress`-флаг.
2. Детекцию (словари, уверенность, очередь ошибок) выполнять в воркере движка.
3. `EngineEvent::ErrorDetected` может приходить асинхронно — карточка появляется с задержкой до ~30 мс, это нормально.
4. Подавление физического ввода во время коррекции остаётся атомарным флагом (`suppress`), поведение не меняется.

**Приёмка**: в журнале за 8-часовой прогон нет ни одной строки «колбэк занял»; в коммите — замер p99/max до и после; коррекция, карточка и пакетный режим работают как раньше (тесты + дымовой прогон).

### P0.2. Убрать блокировки и лишние копии с горячего пути

- `pending_errors_count()` → `AtomicUsize` (сейчас берёт мьютекс состояния).
- `EngineConfig` для колбэка — снимок в `ArcSwap`/`RwLock`, без `clone()` на каждое нажатие.
- `current_layout()` — кэш с TTL 200 мс (смена раскладки — редкое событие).

**Приёмка**: в колбэке нет ни одного `lock()` на пути обычного символа; замеры в коммите.

### P0.3. Диагностика хука

Секция «Диагностика» в настройках (см. §7.9) и журнал: время последнего колбэка, счётчик медленных колбэков, состояние «хук получает клавиатуру / не получает».

### P0.4. Стресс-тест

`crates/klavium-app/examples/hook_budget.rs`: генерирует 10 000 нажатий через `SendInput`, собирает длительности колбэка, печатает p50/p99/max. Используется в приёмке P0.1 и в релизном чек-листе.

## 4. Блок P1a — Интерфейс 2.0 (4–6 дней)

### 4.1. Дизайн-система

Палитра — как в исходном ТЗ (светлая, System Settings-подобная): `BG_WINDOW #F5F5F7`, `BG_SIDEBAR #ECECF1`, `BG_CARD #FFFFFF`, `BORDER_SUBTLE #E3E3E8`, `BORDER_STRONG #C8C8D0`, `TEXT_PRIMARY #1D1D1F`, `TEXT_SECONDARY #6E6E73`, `ACCENT #2563EB`, `ACCENT_TINT #E9EFFD`, `SUCCESS #16A34A`, `WARNING #D97706`, `DANGER #DC2626`, `TRACK #E9E9EE`. Радиусы: карточки 10, кнопки/поля 6, кейкапы 4, тосты 8. Сетка отступов 4/8/12/16/24, паддинг карточки 16, строка настройки 40–44.

Дополнение к исходному ТЗ: **токены сразу в виде двух наборов** (light/dark), переключение — позже (P3); сейчас активен light. Это дешевле, чем потом переписывать константы.

### 4.2. Тема и шрифты

`install_theme(&egui::Context)` в `settings.rs`:

1. Фиксированная светлая тема (`Visuals::light()` + переопределения), независимо от системной.
2. `CornerRadius::same(6)` для виджетов, обводки `BORDER_*`, `selection.bg_fill = ACCENT_TINT`, `hyperlink_color = ACCENT`, слайдер с `.trailing_fill(true)`.
3. Шрифты — цепочка: `SegUIVar.ttf` → `segoeui.ttf` → встроенный egui. **Важно**: на этой машине `SegUIVar.ttf` нет (в `C:\Windows\Fonts` только `segoeui*.ttf`), поэтому шаг 1 — опциональный, не обязательный. Отдельного `seguisb.ttf` (Semibold) тоже нет — «полужирный» делаем `RichText::strong()`, в приёмке не требовать настоящий вес.
4. Размеры: Heading 17, Body 13, Button 13, Small 11.5, Monospace 12.

**Приёмка**: окно светлое при тёмной теме Windows; при переименованном `segoeui.ttf` окно открывается на встроенном шрифте без ошибок.

### 4.3. Каркас

Окно 860×620, минимум 720×520. Сайдбар 220: шапка (иконка 28×28 через `tray::neutral_icon_rgba()`, «Klavium», caption `исправление раскладки · v{env!("CARGO_PKG_VERSION")}`), пункты-строки 34 px с иконками (Lucide через `include_bytes!`, фолбэк — без иконок, никаких ошибок), внизу «Открыть папку данных». Нижняя панель: «Сохранить» (акцентная, неактивна без изменений; `AppConfig: PartialEq` уже есть), «Сбросить» (вторичная), статус с гашением через 4 с, справа подсказка о выходе и «Скрыть в трей». Контент: заголовок 17 + caption, карточки в колонку.

### 4.4. Компоненты

`crates/klavium-ui/src/widgets.rs`: `card`, `card_titled`, `setting_row`, `switch`, `keycap`, `badge`, `progress`, `segmented`, `metric_card`.

Дополнение к исходному ТЗ: `switch` — **миграция существующего `toggle_switch`** из `settings.rs` (не вторая реализация); `setting_row` рисует разделители сам, поэтому убрать текущие `ui.separator()` в секциях, а не дублировать.

Все 8 секций переводятся на карточки/строки. Логика и набор настроек не меняются, кроме новых полей из §5–§7. Кейкапы хоткеев — из `hotkey_label()` (единый формат).

Стиль: обводка 1 px `#3A3D45`, акцентная полоса `#2563EB`, пилюли `#2D2F36` / текст `#DCDEE4`, радиусы как сейчас. Хоткеи в пилюлях уже берутся из конфига (`apply_key`/`hide_key` в `CardRequest`) — не ломать.

### 4.7. Скриншоты и документация

Обновить `docs/images/*` (settings, correction-card, stats, voice), README, `docs/architecture.md` (новые модули).

**Приёмка блока**: `KLAVIUM_APP_SETTINGS_PAGE=*` — все секции без паник; окно не разваливается на 720×520 и 1920×1080; нет «голых» `ui.separator()` как разделителей секций; `clippy --all-targets -D warnings` чистый.

## 5. Блок P1b — Память (2–3 дня)

### 5.1. Ленивая загрузка и выгрузка Whisper

`voice.lazy_load` (default `true`), `voice.unload_after_min` (default 10, 0 — никогда). Статус `EngineStatus::Idle`. Первый `Toggle` → `Loading` + бейдж, по готовности сразу старт диктовки. По простою — дроп движка, `Idle`, лог, однократный `EmptyWorkingSet`. Настройки в секции «Голос»: свитч, поле минут, кнопка «Выгрузить сейчас».

**Приёмка**: замер RSS до/после в коммите (критерий — «RSS в простое ≤ базовый минус размер модели», а не абсолютные 45 МБ); после 10 мин простоя модель выгружена (лог + падение RSS); тест на чистую функцию «пора выгружать» и на сериализацию новых полей.

### 5.2. Компактные словари

FST (`fst` crate): `build.rs` в `klavium-core` читает `data/*_words.txt`, добавляет ё→е-формы, пишет `.fst` в `OUT_DIR`; `dicts.rs` — `include_bytes!` + `fst::Set`. API `contains_english`/`contains_russian`/счётчики сохранить, биграммы не трогать. Фолбэк — блоб + `Vec<u32>` смещений.

**Приёмка**: exe не тяжелее +5 % (ожидается −3…4 МБ), куча −8 МБ; тесты словарей проходят без правки порогов; замеры и итоговый выбор — в doc-комментарии `dicts.rs` и в коммите.

### 5.3. Мелочи

- `EmptyWorkingSet` (после старта ~30 с и после выгрузки модели, не чаще раза в минуту). **Требуется фича `Win32_System_Memory` в `klavium-platform` — сейчас её нет.**
- `stack_size`: фоновые потоки 256 КБ, движок 512 КБ; оконные (оверлей, трей) не трогать.
- Профиль: `codegen-units = 1`, `lto = "fat"`; `panic = "abort"` — только после зелёного `cargo test --workspace` и дымового прогона, иначе не применять.
- `cargo bloat --release --crates` — топ-10 в описание коммита (локально, не в CI).

## 6. Блок P1c — Скорость ввода (1–2 дня)

### 6.1. Вставка длинного текста через буфер

`inject::paste_text(text)`: сохранить текстовый буфер, записать текст, `Ctrl+V` (с меткой), ~120 мс, восстановить. **Дополнение к исходному ТЗ:** перед восстановлением сравнить текущее содержимое буфера с вставленным — если пользователь успел скопировать своё, не восстанавливать. Нетекстовый формат — заменить и залогировать warn. Любая ошибка буфера — фолбэк на посимвольный ввод.

`real_io::send_voice_text`: > 40 символов и `voice.paste_long_text = true` (default) → через буфер, иначе посимвольно. `send_text` (исправление слова) не меняется.

**Приёмка**: 200 символов появляются одним куском < 0,5 с; буфер после диктовки цел; фолбэк проверен; тест на выбор стратегии (чистая функция).

### 6.2. Темп ввода — двумя независимыми пресетами

Исходное ТЗ смешивает коррекцию и диктовку: сейчас коррекция печатает 20 мс (короткий текст) / 10 мс (длинный), а диктовка — 10 мс / 5 мс. Одни общие «20/10» замедлят диктовку вдвое.

Требуется: `typing.speed_correction` и `typing.speed_voice` — `careful | fast | instant`; careful = текущие значения **каждого** пути (коррекция 20/10, диктовка 10/5), fast — вдвое быстрее, instant — 2/1 мс. UI: два `segmented` в «Таймаутах» с пояснениями.

**Приёмка**: careful даёт ровно текущие задержки (тест на маппинг); смена применяется после «Сохранить».

### 6.3. Обрезка тишины (VAD)

Порог = max(шумовой пол × 3, 0.005); шумовой пол — экспоненциальное среднее минимумов за сессию. Обрезать голову/хвост перед распознаванием.

**Приёмка**: юнит-тест на синтетических семплах (тихий хвост обрезан, речь цела); на модели base нет регрессии по времени (замер `examples/whisper_speed`).

### 6.4. Квантованные модели

`q5_1` в `MODELS` + URL в `models.rs`, пометка «быстрее и вдвое легче». Разрешение пути по конфигу — проверить, что выбирается нужный файл.

## 7. Блок P2 — Функции (5–7 дней, по убыванию)

Общее: конфиг `#[serde(default)]`, хоткей — через существующую систему, чистая логика покрыта тестами в `klavium-core`, README дополняется.

### 7.1. Отмена последнего исправления
`hotkeys.correction_undo`, дефолт **`Ctrl+Alt+Z`** (не `Ctrl+Shift+Z`: это redo и, главное, текущее сочетание исправления у пользователя). Движок хранит `LastCorrection { original, corrected, source_layout, target }`; отмена доступна только в том же поле/окне, иначе тихий no-op. В карточке — третья пилюля, если влезает по ширине.
**Приёмка**: `ghbdtn → привет` → отмена возвращает `ghbdtn` и EN-раскладку; после смены окна — no-op; тесты.

### 7.2. Исправление выделенного
`hotkeys.correction_selection`, дефолт **`Ctrl+Alt+X`**. `Ctrl+C` (с меткой) → буфер → детекция по `detect.rs` → буфер → `Ctrl+V` → восстановление (с проверкой содержимого, как в 6.1). Низкая уверенность — тост «Не удалось определить раскладку», ничего не менять. Выключатель «Использовать буфер обмена» (default on).
**Приёмка**: выделенное `ghbdtn vbh` → `привет всем`; буфер цел; пустое выделение — no-op; проверено в Chrome/Edge.

### 7.3. Пользовательский словарь
`data/user_dict.txt` (слово в строке, `!` — стоп-лист). `contains_user`/`is_forbidden`; **чтение без блокировок на горячем пути** — снимок `ArcSwap`, перезагрузка по mtime не чаще раза в 60 с в потоке движка. Стоп-слово не исправляется никогда; слово из словаря повышает уверенность в текущей раскладке. Автодобавления нет: кандидаты (трижды показали и скрыли) — только предложением в настройках.
**Приёмка**: слово из словаря не исправляется; стоп-слово не исправляется; файл перечитывается без перезапуска; тесты.

### 7.4. Правила для приложений
`correction.app_rules: Vec<AppRule { pattern, mode: off|manual }>`, валидация пустого шаблона. `window::foreground_process_exe()` (`OpenProcess` + `QueryFullProcessImageNameW`) **с кэшем по HWND** и fallback «правило не применяется», если процесс не открылся (elevated/защищённые). `off` — коррекция и подсказки выключены, `manual` — только F8. UI: карточка «Приложения» + кнопка «Текущее окно».
**Приёмка**: `windowsterminal.exe → off` отключает коррекцию в терминале и не влияет на блокнот; тест на матчинг.

### 7.5. Пауза коррекции
Трей: «На 30 минут» / «До перезапуска» / «Снять паузу», tooltip с суффиксом «(пауза)». Хоткей по умолчанию — пустой. Состояние — в памяти процесса, **на диск не пишется никогда** (уточнение формулировки исходного ТЗ). Тост при включении/снятии.
**Приёмка**: пауза глушит и авто-исправление, и подсказки; таймер снимает сам; после перезапуска пауза снята.

### 7.6. Push-to-talk
`voice.mode: toggle | push` (default toggle). В `push`: key-down хоткея — старт, key-up — стоп и распознавание. Требуется маршрутизация key-up для этого vk в хуке (сейчас key-up отбрасывается, кроме «немых» клавиш). Бейдж «говорите…».
**Приёмка**: удержание F9 3 с → текст после отпускания; одиночное нажатие в toggle работает как раньше; тест конечного автомата.

### 7.7. Транслитерация
`convert::translit(text, RuToLat | LatToRu)`, таблица ГОСТ 7.79 (B) + частые случаи; хоткей `Ctrl+Alt+T`; работает и на выделении (7.2).
**Приёмка**: ≥ 20 слов в обе стороны в тестах.

### 7.8. Сниппеты
`snippets: Vec<Snippet { trigger, expansion }>` (триггер ≥ 2 символов, без пробелов). Срабатывание — по завершении слова, приоритет выше коррекции; вставка длинного — через 6.1.
**Приёмка**: `;адр` → адрес; конфликт с словарным словом — в пользу сниппета; тесты.

### 7.9. Диагностика ✅ (0.2.7)
Новая секция «Диагностика»: версия, каталог данных, состояние хука (получает клавиатуру / нет, последний колбэк, счётчик медленных), состояние голосового движка, кнопки «Открыть журнал», «Открыть папку данных», «Копировать отчёт» (текст для поддержки).

**Реализовано:** `hook::last_event_age_ms()` и `hook::slow_callback_count()`; `KLAVIUM_APP_SETTINGS_PAGE=diagnostics` для дымового прогона. Признак «хук получает клавиатуру» строится на свежести последнего колбэка — `GetLastInputInfo` обновляется и мышью, поэтому исходная формулировка давала ложные тревоги при клике.

## 11. Риски и открытые вопросы

1. **Снятие хука системой** возможно и при коротких, но частых задержках (антивирус, диск). План: бюджет (P0) + диагностика (7.9). Автопереустановка «на месте» (`Unhook` + `SetWindowsHookEx` в том же потоке) **не работает** — проверено, хук после неё мёртв; если делать самовосстановление, то только через пересоздание потока хука.
2. **Менеджеры буфера обмена** (Ditto, Win+V) увидят наш текст при вставке через буфер (6.1, 7.2). Принять как известное ограничение, предупредить в README.
3. **Raw input для «немых» клавиш** — потенциальное решение проблемы назначения Pause/PrintScreen/ScrollLock. Вне текущего объёма; при необходимости — отдельная задача (регистрация `RIDEV_INPUTSINK`, отдельное окно-приёмник).
4. **Защищённые процессы** (admin/elevated) — `OpenProcess` не откроется; правила приложений для них не работают (fallback, без падения).
5. **Тёмная тема** — токены заложены, переключение позже; сейчас принудительно светлая (в README отметить).
6. **Меню трея** остаётся нативным (muda) и в светлый стиль не попадёт — известное ограничение.
